# 代码使用与计算逻辑说明

本文是项目当前代码的单一操作说明。它同时说明：三个 Python 文件分别做什么、如何运行、数据如何在程序之间流转，以及五个旅游气象指数如何由输入字段计算得到。

## 1. 一句话概览

本项目不预测天气。用户先取得某一未来日期的逐日天气预报，再由程序根据茶卡国家基准气候站的冻结历史基准，输出该日期的五项旅游气象指数。


## 2. 三个代码文件及职责

| 文件 | 作用 | 是否由用户直接运行 |
|---|---|---|
| `src/build_baseline.py` | 程序一。读取历史 Excel，执行质量控制并构建冻结基准 Excel。 | 是。首次部署、历史数据更新或方法版本更新时运行。 |
| `src/calculate_indices.py` | 程序二。读取冻结基准 Excel 和未来某日预报，输出五项指数。 | 是。每次计算某日预报时运行。 |
| `src/tourism_indices.py` | 共享规则库。保存公式、分级、质量控制、基准读写、校验与计算函数。 | 否。由前两个程序自动导入。 |

共享规则库的作用是让“历史建基准”和“未来算指数”使用同一套公式和质控规则，避免两个程序各自复制规则后发生口径漂移。

## 3. 首次使用：安装环境

在项目根目录打开 PowerShell：

```powershell
cd C:\path\to\Tourism-Weather-Index
python -m pip install -r requirements.txt
```

当前运行依赖为 `openpyxl`。命令输出为 UTF-8 JSON。

## 4. 程序一：从历史数据构建冻结基准

### 4.1 何时运行

只在首次使用，或出现以下任一变化时运行：

- 已授权使用的历史工作簿更新；
- 指数公式、阈值、站点参数或质控规则更新；
- 需要建立新的、可追溯的历史基准期。

日常计算未来预报时，不需要重复运行该程序。

### 4.2 运行命令

```powershell
python .\src\build_baseline.py `
  --history ".\data\SHUJU(1).xlsx" `
  --output .\data\baseline_tea_card_v1.xlsx
```

历史文件名含括号时必须加引号，避免 PowerShell 将括号当作语法解析。

### 4.3 输入、处理与输出

输入历史表需要包含：年、月、日、平均气温、最低气温、平均相对湿度、平均 2 分钟风速、日照时数（直接辐射计算值）。数值 `>=999000` 均视为缺测。

程序一执行以下工作：

1. 检查必需字段及日期；
2. 剔除 `999xxx` 缺测值和不合规则数值；
3. 使用固定纬度 36.7833° 计算理论昼长，校验日照时数；
4. 计算历史 UVP、K、最低气温冷位次和着装需求分布；
5. 计算 UVP 与着装需求的 20%/40%/60%/80% 历史分位阈值；
6. 将全部未来计算必需参数写入冻结基准 Excel。

输出的 `baseline_tea_card_v1.xlsx` 有四个工作表：

| 工作表 | 保存内容 | 为什么需要 |
|---|---|---|
| `Metadata` | 结构/方法版本、站点纬度和海拔、海拔因子、基准期、源文件 SHA-256、质控常量 | 确保结果可追溯、可校验。 |
| `Thresholds` | UVP 与着装需求的四个分位阈值 | 把连续值划为五级。 |
| `Distributions` | 排序后的历史最低气温和 K 值 | 未来任意连续输入都能按经验分布计算着装需求。 |
| `Validation` | 各指标实际使用的有效日数 | 检查基准文件完整性。 |

不要手工修改该 Excel。程序二会拒绝结构版本、方法版本、站高、UVP 海拔因子、排序分布或有效样本数不匹配的基准文件。

## 5. 程序二：用未来逐日预报计算五个指数

### 5.1 必填字段

未来预报的统计口径必须与历史数据一致。

| JSON 键 / 命令参数 | 含义 | 单位 |
|---|---|---|
| `date` / `--date` | 预报日期，格式 `YYYY-MM-DD` | 日期 |
| `avg_temp` / `--avg-temp` | 日平均气温 | ℃ |
| `min_temp` / `--min-temp` | 日最低气温 | ℃ |
| `avg_rh` / `--avg-rh` | 日平均相对湿度 | % |
| `avg_wind` / `--avg-wind` | 日平均 2 分钟风速 | m/s |
| `sunshine_hours` / `--sunshine-hours` | 日照时数 | 小时 |

输入范围：气温 -80 至 70℃，湿度 0 至 100%，风速 0 至 100m/s，日照 0 至 24 小时；`>=999000` 被视为缺测。日照超过理论昼长不超过 0.05 小时会自动压到理论昼长，超过 0.05 小时则报错。

### 5.2 推荐方式：JSON 文件输入

建立 UTF-8 编码的预报文件，例如 `forecast.json`：

```json
{
  "date": "2026-07-20",
  "avg_temp": 14.0,
  "min_temp": 6.0,
  "avg_rh": 45,
  "avg_wind": 3.0,
  "sunshine_hours": 10.0
}
```

执行：

```powershell
python .\src\calculate_indices.py `
  --baseline .\data\baseline_tea_card_v1.xlsx `
  --input-json .\examples\forecast.json
```

### 5.3 另一种方式：直接写入命令行

```powershell
python .\src\calculate_indices.py `
  --baseline .\data\baseline_tea_card_v1.xlsx `
  --date 2026-07-20 `
  --avg-temp 14.0 `
  --min-temp 6.0 `
  --avg-rh 45 `
  --avg-wind 3.0 `
  --sunshine-hours 10.0
```

`--input-json` 与六个单项参数只能选一种；不可混用。

### 5.4 程序二的处理顺序

1. 读取并校验冻结基准 Excel；
2. 校验日期、六项预报数据、缺测值与日照时数；
3. 计算 THI 和 K，并映射到九级分值；
4. 由 THI/K 分值计算人体舒适度；
5. 由日期、日照和固定站点参数计算 UVP；
6. 用历史最低气温和 K 的排序分布计算着装保温需求；
7. 返回五项连续指数、等级、质控后输入和本次基准信息。

程序二不读取原始历史工作簿，也不重新拟合阈值。

## 6. 五个指标的计算逻辑

令 `t` 为日平均气温、`tmin` 为日最低气温、`f` 为相对湿度的小数形式、`V` 为日平均 2 分钟风速、`S` 为质控后日照时数。

### 6.1 温湿度指数 THI

```text
THI = (1.8t + 32) - 0.55 × (1 - f) × (1.8t - 26)
```

THI 映射为 -8 至 8 的九级有方向分值：极冷、寒冷、偏冷、偏凉、中性、偏暖、暖热、闷热、极闷热。

### 6.2 风效指数 K

```text
K = -(10 × sqrt(V) + 10.45 - V) × (33 - t) + 8.55 × S
```

K 同样映射为 -8 至 8 的九级有方向分值：酷冷、冷、冷凉、凉、舒适、暖、暖热、热、炎热。此处必须使用日平均 2 分钟风速，不能以最大风速或阵风替代。

### 6.3 人体舒适度 C

```text
A = max(abs(THI_score), abs(K_score))
C = 100 - 12.5 × A
```

使用 THI 与 K 中偏离舒适区更严重的一项，避免冷热抵消。输出为 100、75、50、25 或 0，对应舒适、舒适、基本舒适、较不舒适、不舒适。C 是未通过着装调整的原始天气舒适度。

### 6.4 着装保温需求 D

从冻结基准读取排序后的历史最低气温 `Tmin_hist` 和 K `K_hist`：

```text
Rmin = 100 × P(Tmin_hist ≥ tmin)
RK   = 100 × P(K_hist ≥ K)
D    = max(Rmin, RK)
```

温度越低或 K 越低，冷位次越高。D 取两项中较高的值，用于全天出游的保守行前着装建议。它是 0–100 的相对保温需求，不是物理衣物厚度，也不是 `clo`。

### 6.5 日照紫外暴露潜势 UVP

现有数据没有紫外辐射、云量、臭氧或气溶胶，故该指标不是标准 UVI。它基于日期、日照时数、固定纬度 36.7833° 和固定站高 3087.6m 计算相对直接日照暴露潜势。

```text
UVP_base = 100 × S × sin(正午太阳高度角) / 14.131644170491846
海拔因子 A_alt = 1 + 0.10 × 3087.6 / 1000 = 1.30876
UVP = UVP_base × A_alt
```

海拔因子同时应用于历史基准和未来预报。UVP 不封顶，可能超过 100；它再按冻结的历史分位阈值分为低、较低、中等、较高、高暴露潜势。

## 7. 输出内容与示例

程序二成功时输出 UTF-8 JSON，结构为：

```text
status
input                 # 质控后实际入模的六项数据
indices
  uvp                 # 修正值、未修正值、等级、海拔因子
  clothing            # 相对保温需求、等级、温度/K 冷位次
  comfort             # 舒适度、等级、最大偏离分值
  thi                 # THI、分值、等级
  wind_effect_k       # K、分值、等级
baseline              # 方法版本、基准期、阈值、站点参数、源文件哈希
```

当前示例输入的回归结果为：UVP 88.96、着装需求 19.71、人体舒适度 75、THI 57.44、风效 K -385.14。该结果仅用于验证程序口径，不是对该日期真实天气的结论。

如果输入或基准文件不符合规则，程序输出：

```json
{
  "status": "error",
  "message": "具体错误原因"
}
```
