# 项目交接与方法说明

## 1. 项目目的与明确边界

本项目为茶卡盐湖构建逐日旅游气象指数。最终使用方式是：输入未来某日、与历史站点数据同口径的预报气象变量，直接输出五项指数。

基础数据被用户明确指定为茶卡盐湖附近茶卡国家基准气候站的逐日历史观测。当前历史文件包含一个工作表，共 23,925 条记录，日期覆盖 1961-01-01 至 2026-07-11；有 8 个自然日无记录。项目不宣称站点观测完全等同于景区微气候，只按用户授权将其作为景区的基础气象站。

本项目当前只实现以下五项气象指数，不等同于完整的“旅游适宜度”或“旅游安全”系统。降水、雷电、能见度、最大风速、极大风速、交通和客流等均未计入综合结果。

在五项指数之后，当前程序还输出“综合旅游气象指数”。它是五项结果按本项目确认的第一版权重合成的 0–100 分结果；详细公式、UVP 中等最佳规则、历史阈值和版本边界见 [`COMPOSITE_INDEX.md`](COMPOSITE_INDEX.md)。

## 2. 输入、单位与缺测规则

未来单日输入必须同时提供以下六个字段。

| JSON 字段 | 历史表字段 | 单位 | 使用的指标 |
|---|---|---:|---|
| `date` | 年、月、日 | YYYY-MM-DD | UVP、日照质控 |
| `avg_temp` | 平均气温 | ℃ | THI、K、C、D |
| `min_temp` | 最低气温 | ℃ | D |
| `avg_rh` | 平均相对湿度 | % | THI、C |
| `avg_wind` | 平均2分钟风速 | m/s | K、C、D |
| `sunshine_hours` | 日照时数（直接辐射计算值） | 小时 | UVP、K、C、D |

统一质量控制：

1. 任意数值 `>=999000` 为缺测；源数据中存在 `999999`、`999998`、`999038`、`999990` 等不同形式，均不可参与计算。
2. 相对湿度必须在 0–100；平均气温和最低气温在代码中暂限定为 -80 至 70℃；平均风速限定为 0 至 100m/s；日照时数限定为 0 至 24 小时。
3. 由日期和固定纬度 36.7833° 计算理论昼长。日照时数高于理论昼长不超过 0.05 小时时，修正为理论昼长；超过 0.05 小时即判异常，不输出结果。
4. 输出的 `sunshine_hours` 是质控后的实际入模值。

历史质控后的有效样本数：最低气温 23,894 天，K 23,723 天，UVP 23,751 天，D 23,722 天；THI 23,785 天，人体舒适度 23,629 天。

## 3. 总体依赖关系

```text
日期、日照时数、固定站高 ─────> UVP
平均气温、平均湿度 ─────────> THI ─┐
平均气温、平均风速、日照时数 ─> K ───┼─> 人体舒适度 C
最低气温、K、历史基准 ────────────> 着装保温需求 D
```

THI 与 K 为基础指标。C 只调用 THI 与 K 的分段分值；D 调用最低气温、K 及历史经验分布；UVP 使用日期、日照时数、固定站点纬度和固定站高。海拔不作为 THI、K、C、D 的额外输入。

## 4. 五项指标的精确计算口径

### 4.1 温湿度指数（THI）

令 `t=avg_temp`，`f=avg_rh/100`：

```text
THI = (1.8t + 32) - 0.55 × (1 - f) × (1.8t - 26)
```

分段及有方向分值：

| THI | `THI_score` | `THI_level` |
|---:|---:|---|
| <40 | -8 | 极冷 |
| 40–<45 | -6 | 寒冷 |
| 45–<55 | -4 | 偏冷 |
| 55–<60 | -2 | 偏凉 |
| 60–<65 | 0 | 中性 |
| 65–<70 | 2 | 偏暖 |
| 70–<75 | 4 | 暖热 |
| 75–<80 | 6 | 闷热 |
| ≥80 | 8 | 极闷热 |

### 4.2 风效指数（K）

令 `t=avg_temp`、`V=avg_wind`、`S=sunshine_hours`：

```text
K = -(10 × sqrt(V) + 10.45 - V) × (33 - t) + 8.55 × S
```

未来输入必须使用日平均 2 分钟风速，不能用最大风速、极大风速或阵风替代。

| K | `K_score` | `K_level` |
|---:|---:|---|
| <-1200 | -8 | 酷冷 |
| -1200–<-1000 | -6 | 冷 |
| -1000–<-800 | -4 | 冷凉 |
| -800–<-600 | -2 | 凉 |
| -600–<-300 | 0 | 舒适 |
| -300–<-200 | 2 | 暖 |
| -200–<-50 | 4 | 暖热 |
| -50–<80 | 6 | 热 |
| ≥80 | 8 | 炎热 |

### 4.3 人体舒适度（C）

这是**未通过加衣、遮阳等行为调整的原始天气热舒适度**，不把 UVP、降水等风险混入其中。

```text
A = max(abs(THI_score), abs(K_score))
C = 100 - 12.5 × A
```

`A` 的最不利因子法避免了“一个指标偏冷、另一个偏热，在加总中相互抵消而误判舒适”的问题。输出只会是 100、75、50、25、0：

| C | 级别 |
|---:|---|
| 100 或 75 | 舒适 |
| 50 | 基本舒适 |
| 25 | 较不舒适 |
| 0 | 不舒适 |

历史试算中 C=0 有 9,139 天，约占有效日 38.7%。这是高海拔高寒气候与现有“原始舒适度”定义共同导致的结果，不是代码错误。若未来目标改为“游客按推荐着装后的舒适度”，必须新建另一项指标，不能直接改写 C。

### 4.4 着装保温需求指数（D）

源论文的 ICL 需要太阳辐射强度和活动代谢等数据；本项目没有这些变量，不能输出真实 `clo` 或衣物物理厚度。因此 D 定义为 0–100 的**相对保温需求**。

设历史有效最低气温分布为 `Tmin_hist`，历史有效 K 分布为 `K_hist`：

```text
Rmin = 100 × P(Tmin_hist ≥ Tmin)
RK   = 100 × P(K_hist ≥ K)
D    = max(Rmin, RK)
```

温度或 K 越低，相对冷位次越高。`max` 是已确认的“全天出游行前保守建议”规则：最低气温或日间风效中任一项的保温需求更高，即按更高值输出。

由当前历史基准计算的阈值为 27.991、45.830、67.151、86.813：

| D | 级别 |
|---:|---|
| <27.991 | 极低保温需求 |
| 27.991–<45.830 | 较低保温需求 |
| 45.830–<67.151 | 中等保温需求 |
| 67.151–<86.813 | 较高保温需求 |
| ≥86.813 | 高保温需求 |

注意：最低气温往往发生在夜间或清晨，D 因而适合“全天出游、行前保守着装”而非只反映中午游览。不要把等级直接写成某种衣服；服装文案应作为单独的产品规则维护。

### 4.5 日照紫外暴露潜势指数（UVP）

现有数据没有紫外辐射、总/短波辐射、云量、臭氧或气溶胶。因此不能计算标准紫外线指数 UVI。当前指数名称必须保持为“日照紫外暴露潜势指数”。

令 `d` 为年内日序、`φ=36.7833°`、`S_adj` 为质控后的日照时数。茶卡固定站高 `H=3087.6m`；采用“每升高 1000m，紫外暴露约增加 10%”的近似，得到 `A_alt=1+0.10×H/1000=1.30876`：

```text
δ = 23.45° × sin(2π(284 + d) / 365)
N = (24/π) × arccos(-tan(φ) × tan(δ))
h = arcsin(sin(φ) × sin(δ) + cos(φ) × cos(δ))
UVP_base = 100 × S_adj × sin(h) / 14.131644170491846
UVP = UVP_base × A_alt
```

其中 `N` 是理论昼长，`h` 是正午太阳高度角；14.131644170491846 是以茶卡固定纬度、全年日序计算出的理论最大 `N×sin(h)`。它是归一化参照，不是辐射观测量。代码同时输出未修正的 `unadjusted_value`、修正后的 `value`、`altitude_factor` 与 `station_elevation_m`；修正后的数值不封顶，因此可能超过 100。

同一海拔因子同时应用于历史基准和未来输入。当前历史基准的分级阈值为 36.329、46.897、64.190、87.407：低、较低、中等、较高、高暴露潜势。海拔修正依据 WHO 对海拔与紫外暴露关系的概括性说明；它不补足云量、臭氧、气溶胶或紫外辐射观测，因此该指标**仍不能**解释为 WHO/国际 UVI 的健康风险等级。

方法参考：[WHO，Ultraviolet (UV) radiation: questions and answers](https://www.who.int/news-room/questions-and-answers/item/radiation-ultraviolet-%28uv%29)（海拔每增加 1000m，UV 水平约增加 10%）。这是公式依据，不是本项目新增的气象输入数据。

## 5. 当前实现与输出契约

共享规则模块：`src/tourism_indices.py`。它不再作为命令行入口；其职责是保存五项公式、质控、基准读写和计算函数。

**程序一：`src/build_baseline.py`。** 输入 `--history` 原始历史工作簿和 `--output` 基准 Excel；输出冻结的 `baseline_tea_card_v2.xlsx`。该文件有四个工作表：

- `Metadata`：结构版本、方法版本、源工作簿名称/SHA-256、基准日期范围、纬度、站高、海拔因子和固定质控参数；
- `Thresholds`：UVP、D、综合旅游气象指数的 20%/40%/60%/80% 历史分位阈值；
- `Distributions`：升序的历史最低气温和 K 分布。它们是未来 D 计算连续经验冷位次所必需的参数，不能只保留四个 D 阈值；
- `Validation`：四项分布/阈值构建时的有效日数。

**程序二：`src/calculate_indices.py`。** 输入 `--baseline` 基准 Excel 和一日预报（`--input-json` 或六个单项参数），直接输出 JSON。该程序没有 `--history` 参数，不会读取或重算原始历史数据。加载时会校验基准文件的结构版本、方法版本、站高、海拔因子、分布排序和有效样本数；不一致时返回错误而不是静默计算。

任一必填字段或基准文件无效时，CLI 返回 `{ "status": "error", "message": "..." }`，而不是输出部分结果。

示例 JSON 见 `examples/forecast.json`。当前示例在原始历史文件上测试通过，依次输出：UVP 88.96（高暴露潜势；未修正值 67.97）、D 19.71（极低保温需求）、C 75（舒适）、THI 57.44（偏凉）、K -385.14（舒适）、综合旅游气象指数 76.06（高）。

## 6. 已验证的数据事实与风险

1. 历史数据中的站点经纬度、站高有 14 组组合；主记录为纬度 36.7833、经度 99.0833、站高 3087.6m。UVP 当前固定用 36.7833° 与 3087.6m；后续应把“茶卡盐湖目标点坐标和站高”配置化。
2. 日照时数有 168 条 `999xxx` 缺测，另有 6 条明显超出理论昼长；代码会拒绝这些记录。
3. THI 与 K 都包含温度信息。C 使用最不利因子而非加权相加，避免双重权重与冷热抵消，但两个指标不是统计独立变量。
4. 日均温度、湿度、平均风速和日照时数不同时发生。结果只能解释为逐日指数，不能替代小时级体感预报。
5. THI/K 公式与分段来自用户提供的《阿克苏旅游气象指数研究》截图，作为参考方法使用。论文研究地点不是茶卡；没有茶卡游客问卷、满意度或客流标签，因此阈值尚未按游客真实体验验证。

## 7. 下一位开发者的建议工作顺序

1. **管理基准版本。** 当前已生成 `baseline_tea_card_v2.xlsx`，并在输出中保留版本与源文件 SHA-256。后续若使用新的历史基准期、修改五项规则或修改综合权重，必须生成新文件名/新版本，不能覆盖后让旧预报失去可追溯性。
2. **增加批量接口。** 以 CSV/Excel/JSONL 接收多日预报，逐行复用同一个 `Baseline`，避免每行重复读取 2 万余条历史记录。
3. **补充自动化测试。** 覆盖公式数值、9 档边界、999xxx 缺测、日照接近昼长、日照明显超昼长、闰年和非法字段。
4. **保留原始与分级值。** 面向接口消费者同时输出连续值、分段分值、等级、基准版本和质控状态，不能只保留中文等级。
5. **慎重扩展为综合旅游适宜度。** 若未来要称“旅游适宜度”，必须另行确认并验证降水、雷电、能见度、最大风速等安全风险规则；不要把它们直接塞进 C。
6. **如需标准 UVI 或真实 clo，必须新增数据。** 标准 UVI 需要紫外/辐射及大气变量；真实穿衣保温值需要辐射和活动代谢等数据。现有工作簿不支持这两项。

## 8. 变更约束

- 不要把 UVP 重命名为 UVI。
- 不要把 D 描述成衣物物理厚度或真实 `clo`。
- 不要用最大风速代替平均 2 分钟风速。
- 不要忽略 `999xxx` 缺测编码。
- UVP 的海拔因子必须对历史基准和未来输入同时应用；不得只修改其中一侧。
- 修改任何阈值、纬度、公式或质控条件时，必须升级方法版本并重跑历史检验。
