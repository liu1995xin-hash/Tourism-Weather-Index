# 茶卡盐湖逐日旅游气象指数方法说明

## 1. 文档目的与适用范围

本文档规定“茶卡盐湖逐日旅游气象指数”当前版本的计算口径、数据要求、计算步骤、基准构建方式、输出解释和使用边界。本文档对应代码方法版本 `1.2-composite-index` 与基准文件结构版本 `1.1`。

该方法的用途是：在取得某一未来日期的**逐日气象预报**后，输入与茶卡国家基准气候站历史数据相同统计口径的气象要素，输出五项旅游气象指数及其综合旅游气象指数。方法不预测天气本身；天气预报由外部预报业务提供，本项目只负责将已给出的逐日预报转换为指数结果。

本方法仅使用项目内提供的历史工作簿 `data/SHUJU(1).xlsx` 构建本地历史基准。除固定纬度、固定站高和已确认的计算常数外，不使用外部观测、遥感、客流、问卷或订单数据。

## 2. 指数体系与结果边界

### 2.1 输出指标

程序按以下顺序输出结果：

| 输出键 | 中文名称 | 数值性质 | 主要回答的问题 |
|---|---|---|---|
| `uvp` | 日照紫外暴露潜势指数（UVP） | 本地相对日照暴露潜势，未限定在 0–100 | 当日直接日照暴露潜势相对高低。 |
| `clothing` | 着装保温需求指数（D） | 0–100 的相对经验位次 | 行前应准备多强的保温。 |
| `comfort` | 人体舒适度（C） | 0、25、50、75、100 | 未通过加衣、遮阳等行为调整时的原始热舒适。 |
| `thi` | 温湿度指数（THI） | 连续值及九级方向分值 | 温湿组合偏冷、适中或偏热。 |
| `wind_effect_k` | 风效指数（K） | 连续值及九级方向分值 | 温度、风和日照共同作用下的体感偏冷、适中或偏热。 |
| `tourism_composite` | 综合旅游气象指数（TI） | 0–100 的加权综合值 | 五项气象条件在既定规则下的综合历史位置。 |

### 2.2 不属于本方法的内容

TI 不是完整的“旅游安全指数”或“旅游适宜度结论”。当前方法不含降水、积雪、雷电、能见度、最大风速、极大风速、道路交通、景区承载、客流、人体活动强度和游客健康状况等因素。因此，不得仅凭 TI 或任一单项指数作出安全放行、医疗风险或游客满意度判断。

UVP 是根据日期、日照时数和固定站点参数计算的**日照紫外暴露潜势**，不是国际标准紫外线指数（UVI），也不代表实际红斑紫外辐射强度。现有数据不包含紫外辐射、云量、臭氧和气溶胶，不能据此计算标准 UVI。

## 3. 数据口径与输入要求

### 3.1 未来预报输入

程序二每次计算一日，需要六个字段：

| 字段 | 含义 | 单位 | 允许范围 |
|---|---|---:|---:|
| `date` | 目标日期，格式 `YYYY-MM-DD` | 日期 | 合法日历日期 |
| `avg_temp` | 日平均气温，记为 `T` | ℃ | −80 至 70 |
| `min_temp` | 日最低气温，记为 `Tmin` | ℃ | −80 至 70 |
| `avg_rh` | 日平均相对湿度，记为 `RH` | % | 0 至 100 |
| `avg_wind` | 日平均 2 分钟风速，记为 `V` | m/s | 0 至 100 |
| `sunshine_hours` | 日照时数，记为 `S` | h | 0 至 24，且须符合理论昼长限制 |

输入必须是逐日统计值。特别是，`avg_wind` 必须为日平均 2 分钟风速；阵风、最大风速或极大风速不能直接替代。历史工作簿中的最高气温字段不参与当前五项指数和 TI 的计算，也不是程序二输入字段。

### 3.2 缺测与有效性处理

任何数值 `>=999000` 均按缺测处理。未来预报中出现缺测、非数值、无穷值或超出上述范围的数值时，程序二停止并返回输入错误，不输出部分结果。

日照时数还需通过理论昼长校验。设目标日期的理论昼长为 `N`：

- 当 `S > N + 0.05` 小时时，输入被拒绝；
- 当 `N < S <= N + 0.05` 小时时，认为可能存在舍入误差，实际参与计算的日照时数取 `N`；
- 当 `S <= N` 时，保留原始 `S`。

历史基准构建时，无法通过日照校验的记录不参与依赖日照的 UVP、K、D、C 和 TI 计算；其他字段仍可按各自有效性进入相应的历史分布。因此，各指标的历史有效样本数可能不同。

## 4. 固定参数与太阳几何

本方法固定使用以下站点参数和常数：

| 参数 | 符号或配置键 | 当前值 | 用途 |
|---|---|---:|---|
| 固定纬度 | `STATION_LATITUDE_DEG` | 36.7833° | 计算太阳几何和理论昼长。 |
| 固定站高 | `STATION_ELEVATION_M` | 3087.6 m | 仅用于 UVP 海拔近似修正。 |
| 缺测阈值 | `MISSING_SENTINEL` | 999000 | 大于等于该值即视为缺测。 |
| 日照容差 | `SUNSHINE_TOLERANCE_HOURS` | 0.05 h | 理论昼长校验容差。 |
| UVP 归一化常数 | `UVP_REFERENCE_MAX` | 14.131644170491846 | UVP 计算常数。 |
| 每千米海拔增幅 | `UVP_ALTITUDE_INCREASE_PER_1000M` | 0.10 | UVP 海拔因子参数。 |

对一年中的第 `d` 日，太阳赤纬、理论昼长和正午太阳高度角的计算为：

```text
φ = 36.7833°
δ = 23.45° × sin[2π × (284 + d) / 365]
ω = arccos(−tan(φ) × tan(δ))
N = 2 × degrees(ω) / 15
h₀ = arcsin[sin(φ) × sin(δ) + cos(φ) × cos(δ)]
```

式中，三角函数计算前将角度转换为弧度；`N` 的单位为小时。程序使用 `sin(h₀)` 的非负值参与 UVP 计算。

## 5. 两个程序的职责与数据流

### 5.1 程序一：历史基准构建

入口程序为 `src/build_baseline.py`。它读取原始历史工作簿，执行字段检查和质量控制，并构建冻结基准 Excel。该程序只应在首次部署、历史工作簿经授权更新、固定参数改变或方法版本升级时运行。

历史工作簿必须至少包含下列列名：`年`、`月`、`日`、`平均气温`、`最低气温`、`平均相对湿度`、`平均2分钟风速`、`日照时数（直接辐射计算值）`。

对于通过日期解析的历史记录，程序分别建立以下数据对象：

1. 有效最低气温排序分布；
2. 有效风效指数 K 排序分布；
3. 有效 UVP 排序分布；
4. 同时具有有效 `Tmin` 和 K 的记录，用于构建 D 的历史分布；
5. 六项输入均有效的完整记录，用于计算 TI 的历史分布。

程序按 20%、40%、60%、80% 分位点计算 UVP、D 和 TI 的五级分段阈值。分位数采用线性插值：对长度为 `n` 的升序序列和概率 `p`，位置为 `(n−1)×p`，在相邻有序值之间线性插值。

### 5.2 冻结基准文件

当前基准文件为 `data/baseline_tea_card_v2.xlsx`，含四个工作表：

| 工作表 | 内容 | 作用 |
|---|---|---|
| `Metadata` | 方法/结构版本、站点参数、源工作簿 SHA-256、质量控制参数、TI 权重和 UVP 子得分规则 | 追溯与口径一致性校验。 |
| `Thresholds` | UVP、D、TI 的 20%/40%/60%/80% 阈值 | 将连续结果划为五级。 |
| `Distributions` | 升序的历史 `Tmin` 和 K | 未来日期计算 D 的连续经验冷位次。 |
| `Validation` | 各项构建时的有效样本数 | 检查分布与基准完整性。 |

程序二加载基准时会校验结构版本、方法版本、站高、UVP 海拔因子、TI 权重、UVP 五档子得分、阈值完整性、历史分布排序和有效样本数。任何不一致都会报错；程序不会静默使用不匹配的基准。

### 5.3 程序二：未来逐日预报计算

入口程序为 `src/calculate_indices.py`。它只读取冻结基准和一日预报，不读取原始历史工作簿，也不重算历史分布或阈值。桌面程序 `src/tourism_index_gui.py` 是程序二的图形界面封装，使用相同的规则模块。

两程序共同调用 `src/tourism_indices.py`，因此单项公式、质量控制、分级规则和综合指数口径在历史构建与未来计算中保持一致。

## 6. 五项指数的计算口径

### 6.1 温湿度指数（THI）

先将湿度百分数换算为比例：

```text
f = RH / 100
THI = (1.8T + 32) − 0.55 × (1 − f) × (1.8T − 26)
```

THI 按以下区间映射为方向分值 `score_THI` 和热感等级。阈值采用“左闭右开”的实现方式：除第一档外，恰好等于某一阈值的值进入较高一档。

| THI 区间 | `score_THI` | 等级 |
|---|---:|---|
| `<40` | −8 | 极冷 |
| `40–<45` | −6 | 寒冷 |
| `45–<55` | −4 | 偏冷 |
| `55–<60` | −2 | 偏凉 |
| `60–<65` | 0 | 中性 |
| `65–<70` | 2 | 偏暖 |
| `70–<75` | 4 | 暖热 |
| `75–<80` | 6 | 闷热 |
| `≥80` | 8 | 极闷热 |

### 6.2 风效指数（K）

```text
K = −(10 × √V + 10.45 − V) × (33 − T) + 8.55 × S
```

K 按以下区间映射为方向分值 `score_K` 和等级：

| K 区间 | `score_K` | 等级 |
|---|---:|---|
| `<−1200` | −8 | 酷冷 |
| `−1200–<−1000` | −6 | 冷 |
| `−1000–<−800` | −4 | 冷凉 |
| `−800–<−600` | −2 | 凉 |
| `−600–<−300` | 0 | 舒适 |
| `−300–<−200` | 2 | 暖 |
| `−200–<−50` | 4 | 暖热 |
| `−50–<80` | 6 | 热 |
| `≥80` | 8 | 炎热 |

### 6.3 人体舒适度（C）

C 使用 THI 和 K 的九级方向分值，不直接使用它们的连续值：

```text
A = max(|score_THI|, |score_K|)
C = 100 − 12.5 × A
```

`A` 表示两个体感指标中偏离中性状态更严重的程度。因此，THI 与 K 的冷热方向不会相互抵消；只要任一项偏离更大，C 即按该不利程度降低。

| C 值 | 等级 |
|---:|---|
| 100 或 75 | 舒适 |
| 50 | 基本舒适 |
| 25 | 较不舒适 |
| 0 | 不舒适 |

### 6.4 着装保温需求指数（D）

D 用于表达“全天出游、行前保守准备”所需的相对保温程度。它不是衣物毫米厚度，也不是真实人体服装热阻 `clo`。

对一个升序历史分布 `X_hist`，当前值为 `x`，定义冷位次：

```text
coldRank(X_hist, x) = 100 × [n − lower_bound(X_hist, x)] / n
```

其中，`n` 为历史分布长度，`lower_bound` 是第一个不小于 `x` 的有序位置。因此，当前值越低，在“低值更冷”的意义下冷位次越高；相同值会一并计入“不低于当前值”的历史记录。

```text
R_Tmin = coldRank(Tmin_hist, Tmin)
R_K    = coldRank(K_hist, K)
D      = max(R_Tmin, R_K)
```

`D` 取最低气温和 K 两个冷位次中的较大值，避免“某一项明显偏冷”被另一项抵消。当前本地历史五级阈值为：

| 阈值序号 | 值 |
|---|---:|
| 20% | 27.991 |
| 40% | 45.830 |
| 60% | 67.151 |
| 80% | 86.813 |

据此从低到高划分为：极低保温需求、较低保温需求、中等保温需求、较高保温需求、高保温需求。

### 6.5 日照紫外暴露潜势指数（UVP）

先基于日期、归一化日照时数和正午太阳高度角计算未修正值：

```text
UVP_raw = 100 × S × sin(h₀) / 14.131644170491846
```

再使用固定站高的近似海拔因子：

```text
F_alt = 1 + 0.10 × 3087.6 / 1000 = 1.30876
UVP   = UVP_raw × F_alt
```

海拔因子同时用于历史基准和未来预报；因此它会改变 UVP 的绝对数值和阈值尺度，但不改变同一固定站点历史样本之间的相对排序。除 UVP 外，THI、K、C、D 不额外引入海拔参数。

当前 UVP 本地历史五级阈值为：

| 阈值序号 | 值 |
|---|---:|
| 20% | 36.329 |
| 40% | 46.897 |
| 60% | 64.190 |
| 80% | 87.407 |

据此从低到高划分为：低暴露潜势、较低暴露潜势、中等暴露潜势、较高暴露潜势、高暴露潜势。

## 7. 综合旅游气象指数（TI）

### 7.1 子得分转换

TI 以五项原始结果为输入，但不直接对不同量纲的原始值相加，而是先转换为 0–100 的子得分：

```text
S_C   = C
S_THI = 100 − 12.5 × |score_THI|
S_K   = 100 − 12.5 × |score_K|
S_D   = 100 − D
```

UVP 采用“中等最佳”的五档偏好映射。先按本地历史 UVP 阈值确定等级序号，再按下表赋分：

| UVP 历史等级 | 低 | 较低 | 中等 | 较高 | 高 |
|---|---:|---:|---:|---:|---:|
| `S_UVP` | 50 | 75 | 100 | 75 | 50 |

该映射表达的是已确认的旅游日照偏好规则：适度日照条件的子得分最高，过低或过高均降低得分。它不是 UVP 健康风险分级。

### 7.2 合成公式和权重

```text
TI = 0.35 × S_C
   + 0.15 × S_THI
   + 0.15 × S_K
   + 0.20 × S_D
   + 0.15 × S_UVP
```

权重之和为 1。C 已使用 THI 与 K 的不利方向分值，D 也使用 K；当前口径仍保留 THI、K 的直接贡献，但各自直接权重设为 0.15。该处理是当前项目确认的设计规则，不是由游客问卷、客流、订单或满意度数据估计得到的统计权重。

### 7.3 TI 分级

对所有六项输入均有效的历史日，按前述步骤计算 TI，并以 20%、40%、60%、80% 分位点形成五级阈值。当前基准期为 1961-01-01 至 2026-07-11，TI 完整样本数为 23,628 天：

| TI 区间（展示精度） | 输出等级 |
|---|---|
| `<21.349` | 极低 |
| `21.349–<36.745` | 较低 |
| `36.745–<58.937` | 中等 |
| `58.937–<69.944` | 较高 |
| `≥69.944` | 高 |

TI 等级仅表示结果相对于当前茶卡历史气象日的综合位置，不代表游客满意度概率、健康风险概率或旅游安全等级。

## 8. 可追溯性、版本管理与复现

每次程序二输出均包含方法版本、基准期、UVP/D/TI 阈值、站高、UVP 海拔因子、历史源工作簿名称及 SHA-256。应将该输出与对应的预报输入一并保存，以便复核某一日期的计算口径。

当出现以下任一情况时，必须重新运行程序一、生成新的版本化基准文件，并同步升级方法版本或文件名：

1. 原始历史工作簿发生授权更新；
2. 输入字段映射、缺测规则、固定站点参数或日照校验规则改变；
3. THI、K、C、D、UVP 或 TI 的公式、阈值、权重、UVP 子得分规则改变；
4. 基准期定义改变。

不得手工修改现有冻结基准或用新内容覆盖旧版本后继续沿用旧的结果解释。

## 9. 计算精度、边界与实现细节

### 9.1 完整精度参与计算

UVP、D、TI 的分位阈值在基准 Excel 中保留完整浮点精度。本文、流程图及输出元数据中的三位小数仅为展示精度。程序使用完整精度阈值比较，不能将本文的三位小数复制到代码中替代基准参数。精确复现应读取同一版本的基准工作簿。

五项指标的计算结果和 TI 子得分在内部保留计算精度。TI 使用尚未四舍五入的 D、UVP 及相关分值合成；不能将输出 JSON 中已保留两位小数的字段重新加权后，要求与内部计算在所有边界情况下完全相同。

各项连续结果、D 冷位次和 TI 子得分在输出时保留两位小数；质控后的日照时数保留四位小数。等级判定先于输出舍入，因此某个显示值可能看似等于展示阈值，却仍属于较低一档。

### 9.2 阈值包含规则

THI 和 K 按代码列出的升序阈值逐个比较。UVP、D、TI 同样采用 `value < threshold` 规则：恰好等于完整精度阈值的数值进入更高一档。五级阈值依次记为 q20、q40、q60、q80 时，区间为 `x<q20`、`q20<=x<q40`、`q40<=x<q60`、`q60<=x<q80`、`x>=q80`。

### 9.3 历史样本使用方式

所有日期、月份和季节共同构成一套全历史基准；当前没有按月或按季节建立基准。Tmin 分布与 K 分布分别使用各自有效记录，因此两者的样本数不必相同。D 使用两套分布计算冷位次，再取较大值；TI 历史样本仅采用日期、T、Tmin、RH、V、S 全部有效的记录。

每个历史日的 D 由包含该日有效观测的完整历史分布计算。该过程用于建立本项目的描述性历史基准，未采用留一法或时间序列交叉验证，也不构成预测模型的独立验证。

程序一按日期解析成功的历史行记录基准起止日期，该日期范围不是所有指标共同有效日期的交集。源工作簿 SHA-256 用于标识原始文件；程序二返回该标识，但不重新读取源文件核验。

### 9.4 参数来源与配置边界

当前并未通过回归模型拟合 THI、K 公式系数或 TI 权重。历史数据产生的参数是经验分布和分位阈值；THI/K 系数与分段、C/D 规则、UVP 几何与海拔规则、TI 权重及 UVP 中等最佳评分均为当前版本已确定的方法规则。

基准 Excel 是两个程序之间的历史参数接口。公式及 TI 权重仍由共享模块定义；权重同时写入 Excel 作为一致性校验信息。手工修改 Excel 权重不会形成一个新方法，程序加载时会拒绝与当前代码不一致的权重。

## 10. 当前限制与后续验证

THI、K 的公式与分段来自用户提供的《阿克苏旅游气象指数研究》截图，尚未由茶卡游客体感标签验证。论文原始资料位于 `sources/aksu-tourism-climate-index-paper.jpg`，不能将截图解释为已完成全文、公式排版或完整文献的复核。

当前 TI 权重和 UVP 偏好规则没有游客满意度、客流、订单或问卷数据的统计支持，应明确标记为项目已确认的第一版设计规则。参考资料与方法决策的既有记录见 [项目上下文](PROJECT_CONTEXT.md) 和 [综合指数说明](COMPOSITE_INDEX.md)。

UVP 受限于日期和日照时数输入；D 受限于历史相对冷位次。二者分别不能解释为标准 UVI 和真实服装热阻。五项指标和 TI 都以逐日输入计算，不提供小时级结论，也不包含独立的旅游安全风险模块。
